# 공통 모델 선택 — Teams와 Workflow

역할별 모델 표는 추천값이지 강제값이 아니다. 사용자 선택이 모든 프리셋·예제·
심부름꾼·검증자 기본값보다 우선한다. 모델 명시는 유지하지만 특정 모델로 고정하지 않는다.
이 선택은 새로 호출할 네이티브 Claude 에이전트에 적용한다. 현재 호스트 모델은 자동으로 바꾸지 않는다.

**기본 선택지는 Fable·Opus·Sonnet이다.** 기계적 처리·심부름꾼·외부 CLI shim은
Sonnet을 기본으로 하며, 비용 절약을 이유로 Haiku를 자동 추천하거나 대체하지 않는다.
Haiku는 사용자가 명시적으로 요청한 역할에만 예외적으로 허용한다.

## 언제 묻나

- Teams: 역할과 태스크 ID를 정한 뒤 Step 5의 구성 확인 AskUserQuestion에 모델 문항을 함께 넣는다.
- Workflow: W1에서 단계와 phase 이름을 정한 뒤, 스크립트를 작성하기 전에 같은 설계 확인 질문에 넣는다.
- 이미 "Fable 중심", "전부 Opus", "수집 Sonnet, 검증 Fable"처럼 지정했다면 그 범위는 다시 묻지 않는다.
  미지정 역할이 남았을 때만 나머지를 묻는다. "추천대로"도 명시적 선택이다.
- 선택 후 요약만 출력하고 끝내지 않는다. 실제 매핑을 저장한 뒤 다음 준비 단계로 진행한다.
- 모드나 구성 변경이 모델 배정에도 영향을 주면 변경분만 확인한다.

## AskUserQuestion 호출

먼저 이번 작업의 실제 역할/단계와 추천 배정을 보여준다. 예:
`수집: Sonnet / 검증: Opus / 종합: Opus`. 고정된 속도·가격·품질 향상률은 제시하지 않는다.
다음 문항을 기존 승인 콜의 `questions` 배열에 포함한다. 다른 언어의 사용자에게는
라벨·설명을 번역하되 Fable/Opus/Sonnet 명칭은 유지한다. 별도 추천 버튼은 만들지 않고,
이번 작업에 추천하는 옵션을 첫 번째로 옮겨 "(추천)"을 붙인다. Fable은 현재 호스트의
연결과 네이티브 `fable` 별칭 지원이 확인됐을 때만 실행 가능한 선택으로 안내한다.

```json
{
  "questions": [{
    "header": "모델 구성",
    "question": "이번 작업의 에이전트 모델을 어떻게 배정할까요?",
    "options": [
      {"label": "Fable 중심", "description": "생산·분석·검증·종합은 Fable, 단순 기계적 처리는 Sonnet을 제안합니다. 현재 호스트의 Fable 연결을 확인한 뒤 실행합니다."},
      {"label": "Opus 중심", "description": "생산·분석·검증·종합은 Opus, 단순 기계적 처리는 Sonnet을 제안합니다. 실제 배정을 확인하고 실행합니다."},
      {"label": "Sonnet 중심", "description": "단순 기계적 처리를 포함해 모든 역할에 Sonnet을 제안합니다. 실제 배정을 확인하고 실행합니다."},
      {"label": "역할별 직접 지정", "description": "각 역할이나 단계에 Fable·Opus·Sonnet을 직접 지정합니다. Haiku는 명시적으로 요청할 때만 사용합니다."}
    ],
    "multiSelect": false
  }]
}
```

직접 지정은 실제 역할/단계별 미결만 한 번에 묻는다. "전부 Fable" 또는 "전부 Opus"라고
지정한 경우는 기계적 처리까지 그 모델이며, "중심" 구성의 Sonnet으로 바꾸지 않는다.
사용자가 모두 Sonnet 또는 Haiku로 지정해도 임의로 상향·하향하지 않는다.
위험한 품질 저하가 예상되면 설명하고 변경 승인을 받되, 승인 전에는 원래 선택을 보존한다.

## 선택 기록과 실제 호출

프로필 이름이 아니라 **태스크/phase별 네이티브 모델 별칭 맵**이 실행 기준이다:

```json
{
  "model_selection": {
    "profile": "custom",
    "models": {
      "수집": "opus",
      "검증": "fable",
      "종합": "opus"
    }
  }
}
```

- 현재 세션의 런 장부 최상위 `model_selection`에 저장한다.
- Teams: 키는 `task.id`. 승인 계획의 `model_selection`과 `tasks[].model`에 같은 값을 넣는다.
  준비기는 두 값이 다르면 거부한다. 수동 스폰의 `name`(없으면 `description`)도
  같은 ID로 전달한다. 스폰 훅이 현재 세션의 선택과 실제 model을 대조한다.
- Workflow: 키는 모든 `agent()`의 실제 `phase` 문자열. 같은 phase의 에이전트는 같은 선택을 쓴다.
  역할별로 모델이 다르면 phase도 구분한다. `model`과 `phase`는 명시적 문자열 리터럴로 작성한다.
- Workflow 사전 검사: `node scripts/wf-lint.js workflow.js --models-json '<model_selection JSON>'`.
  실행 훅도 같은 세션 장부의 선택과 스크립트를 대조한다.
- `profile`은 설명용이다. 실제 맵을 `profile` 이름으로 재계산하거나 덮어쓰지 않는다.
- Fable은 네이티브 `model: "fable"`로 호출한다. 전체 ID
  `claude-fable-5-1[1m]`은 모델 기록에 쓰는 값이지 Agent 인자가 아니다.
  실제 Agent가 허용하는 값은 `opus / sonnet / haiku / fable`이다.
- 태스크/단계 ID 누락·추가·모델 불일치는 수정한 뒤 실행한다. 사용자 선택 자체를 고쳐 통과시키지 않는다.
- 모델 선택이 없는 레거시 실행의 호환 경로는 남지만, 새 모델 선택 흐름은 반드시 맵을 기록한다.

선택 검사는 일반 JavaScript 파서가 아니다. 직접 `agent(prompt, {...})`를 호출하고
옵션은 `schema: SCHEMA`처럼 키·값을 풀어 쓴다. 동적 옵션·별칭 호출·계산 키·spread·
getter·동적 코드 로딩처럼 정적으로 확인할 수 없는 호출은 추측하지 않고 차단한다.
일반 나눗셈·정규식은 지원하지만 중괄호 직후 `/`처럼 문맥이 모호한 구문이나 `v` 정규식은
전체 파서가 필요하므로 거부한다. 이름만으로 실행하는
저장 Workflow도 선택 대조를 위해 실제 script 또는 scriptPath를 제공해야 한다.

## 가용성과 실패

Fable의 연결 경로는 실행 호스트의 유효한 설정을 따른다. 기존 세션의 모델이나
전역 `ANTHROPIC_BASE_URL`을 변경하지 않는다. 설정에 Fable 이름이 있다는 사실과
Agent/Workflow가 `fable` 별칭을 실제로 지원한다는 사실을 구분해 확인한다.
지원하지 않는 호스트에서는 Opus 별칭으로 속여 실행하지 않고 제한을 알린다.
연결 오류·모델 거부는 아래 재선택 절차를 따른다.

**요청 별칭과 실행 모델 증거를 분리한다.** 런 장부의 별도 `model_runtime`에
유효한 연결 URL(인증정보 제외)과, 각 태스크의 요청 별칭·자식 결과의 `resolvedModel`·
확인 가능한 컨텍스트 크기를 기록한다. 예: `fable` 요청, `claude-fable-5-1` 응답,
`contextWindow: 1000000`. 부모 모델 정보나 에이전트의 자기소개로 자식 모델을 추정하지 않는다.
메타데이터가 없으면 미확인으로 기록한다. 응답이 다른 모델 family를 보고하면 배정 불일치로
보고하고 그 결과를 Fable 결과로 채택하지 않는다.

별칭 해석은 호스트가 맡으므로 특정 버전·컨텍스트의 영구 고정을 보장하지 않는다.
사용자가 전체 ID 고정을 요구하면 이 제한을 먼저 알리고, 전역 설정을 몰래 바꾸지 않는다.

호스트에서 실제로 확인한 모델 목록이 있을 때만 `available_models` 배열을 기록한다.
목록을 확인하지 못했다면 생략하고 미확인임을 밝힌다. CLI 설치나 별칭 존재만으로
해당 계정의 모든 모델 사용 권한이 확인됐다고 주장하지 않는다.

선택 모델이 확인한 목록에 없거나 실제 실행에서 거부되면 자동 대체하지 않는다.
AskUserQuestion으로 재시도·다른 모델·취소를 선택받고, 변경을 승인받은 뒤 맵을 갱신한다.
모델을 바꾼 재시도는 같은 조건의 결과처럼 보고하지 않는다.

검증 에이전트의 독립 컨텍스트·읽기 전용 규칙은 모델 선택과 별개로 유지한다.
같은 Claude family를 선택하면 교차 family 검증을 했다고 부르지 않는다.
Codex/Grok/agy 등 외부 CLI와 그 내부 모델은 별도 자원 선택이다. 네이티브 Opus를
명시한 역할을 자동으로 외부 CLI에 넘기지 않는다.
